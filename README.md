# blockMesh GUI – which files to put on GitHub

## Files to save on GitHub

- `gui/server.py`
- `gui/index.html`
- `gui/vendor/three.min.js`
- `gui/vendor/OrbitControls.js`
- `car_simplified.stl`
- `system/sdf.py`
- `system/make_car_blockMeshDict.py`
- `system/build_car_sdf.py`
- `system/extract_car_sdf_surface.py`
- `system/splits.json` (optional)
- `README.md`

Details, what to leave out, and how to run are below.

A browser GUI for splitting, projecting and grading a car `blockMeshDict`
(OpenFOAM 12). The server is Python standard library plus numpy.

## Commit these

Keep the case folder layout exactly as below. `server.py` finds everything
relative to its own location (`gui/..` is the case folder).

```
<case>/
├── car_simplified.stl                  car geometry (the "STL" snap target)
├── gui/
│   ├── server.py                       backend  (edited in this project)
│   ├── index.html                      frontend (edited in this project)
│   └── vendor/
│       ├── three.min.js                served offline by the server
│       └── OrbitControls.js
└── system/
    ├── sdf.py                          distance-field loader (imported by server.py)
    ├── make_car_blockMeshDict.py       generator used by "Write blockMeshDict"
    ├── build_car_sdf.py                builds the distance field
    ├── extract_car_sdf_surface.py      extracts the smooth surface mesh
    ├── controlDict, fvSchemes, fvSolution   (your normal OpenFOAM case files)
    └── splits.json                     optional: saved splits, projections, dead/live blocks
```

`server.py` and `index.html` are the two files changed in this project.
The other files come from your original setup; I haven't seen them, so check
the list against your own case folder.

## Do NOT commit (generated, large or machine-specific)

system/car_sdf_surface.npz         rebuilt by the "Distance field" button

Tip: if the `.stl` or `.npy` files are big (over about 50 MB), use Git LFS or
leave them out and say in this README where to get them. Commit
`system/blockMeshDict` only if you want a snapshot of one specific mesh.

## Run

```
cd <case>
python3 gui/server.py 8765        # then open http://localhost:8765
```

Needs Python 3 with numpy, and OpenFOAM 12 installed at
`/opt/openfoam12` (blockMesh, checkMesh and foamToVTK are run through
`source /opt/openfoam12/etc/bashrc`).

## Typical workflow

1. **Distance field** – build the smooth surface (once, or after a geometry change).
2. Set splits, then **Write blockMeshDict**.
3. **Update projection** – project the surface vertices onto the car.
4. Fix single vertices with **Select / Slide vertex**, **Nearest surface**
   (snaps to the STL), **Smooth surface** (snaps to the distance-field mesh)
   and **Undo projection**. 
   The **Undo** / **Redo** buttons at the top of the left panel (also Ctrl+Z / Ctrl+Y)
   step back and forward through everything: splits, live/dead blocks, block cell
   counts and these vertex moves.
5. **grading** switch (Blocks panel): *off* (generator default), *block grading* (one ratio per direction per block, outer slabs matched to the inner cell size) or *edge grading* (every edge of the live region gets its own ratio from the cell sizes at its two ends; written as `edgeGrading`). The chosen mode is re-applied on every write.
6. **Run blockMesh**, then **Run checkMesh**. Problem cells and faces show in
   the visibility list: negative volume (red), non-orthogonal (orange),
   highly skew (light green), face pyramid errors (cyan), high aspect ratio
   (purple).
